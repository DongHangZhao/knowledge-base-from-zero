# 知识库检索（示例模块说明）

**简体中文** ｜ [English](检索.example.en.md)

> 这是「一个模块一个 README」的示例写法：**用途 / 用法 / 调用链路 / 踩过的坑 / 验收**。
> 照着改，别照抄。

## 用途

把 `wiki/` 的 Markdown 建成 SQLite FTS5 索引，让 AI「先检索再作答」，
每条结论都带文件路径，而不是凭记忆编路径。

对应架构里的**链路 B（索引链路）**：`md → kb.db`，派生层，可删可重建。

## 用法

```bash
python modules/检索/build.py                    # 增量建库（改完 md 必跑）
python modules/检索/build.py --full             # 全量重建（换分词器时）
python modules/检索/search.py "关键词" --topk 5  # 检索
python modules/检索/db_admin.py health          # 体检
python modules/检索/db_admin.py backup --keep 8  # 备份（VACUUM INTO，不能直接拷）
```

## 调用链路

```
scan(md) → hash 比对 → 未变跳过 / 变了重写
        → docs（元数据）+ docs_fts（整篇倒排）
        → split_chunks（按标题层级）→ chunks + chunks_fts
search(query) → 整篇 ⊕ 分块 → RRF 融合 → 统一落回 doc.path
```

## 踩过的坑

1. **FTS5 external content 表不能直接 DELETE** → 用普通 FTS5 表（内容自存）。
2. **SQL 注释只能 `--`**，写 `#` 直接语法错误。
3. **换分词器必须 `--full`**，否则建库/查询分词不一致，命中率腰斩且不报错。
4. **WAL 模式不能直接 `cp kb.db`** → `VACUUM INTO`。
5. **分块单独用是负优化**（丢全文词频），必须与整篇融合。

## 验收

- `build` 两次，第二次全部「未变」；
- 删一个 md 再 build，索引里同步消失；
- 随机抽 3 条结果，path 复制到文件管理器**确实存在**；
- 问一个库内问题，AI 能答出并附路径；问库外的，明确说「未收录」。
