## 这是什么

一套**把零散资料管起来、让 AI 真正能复用你知识**的体系。它解决三件事：

1. **资料不会越堆越乱** —— 用固定的目录架构（原件库 / 合成库 / 能力区 / 产物区）替代「下载→桌面→遗忘」。
2. **AI 有唯一真相源** —— 一份 `AGENTS.md` 让任意 AI 工具（Codex / Claude Code / Qoder / Trae / Cursor）接手时立刻懂规则、懂背景、懂红线。
3. **零散系统集中入口 + 每日高频优先** —— 配套「知识库体系门户」把几十个脚本 / 技能卡片 / 项目聚到一个仪表盘，按使用热度每日排序。

本仓库包含：

| 内容 | 路径 | 说明 |

| 从零到一指南 | 本文件 `README.md` | 你正在读 |

| 示例模板 | `templates/` | AGENTS.md / wiki / modules / 提示词资产 的空白示例 |

## 一、核心理念：Karpathy LLM Wiki + AI 外置大脑

把知识库当成「LLM 写并维护的维基」：

- **人类**负责产生原材料、做最终判断；
- **AI** 负责归档、合成、检索、复用；
- **系统**负责让上面三者不靠记忆、不靠人盯。

关键认知：**规则不分散在各个 AI 工具里**，而是集中在一份跨工具通用的 `AGENTS.md`。换工具 = 换一个能读这份文件的 AI，而不是重新教一遍。

## 二、架构：四区 + 一份真相源 + 两条链路

```
my-knowledge-base/
├── AGENTS.md            # 🔴 唯一真相源：你是谁/怎么说话/红线/知识在哪/怎么查
├── raw/                 # 不可变原件（下载的 PDF/图/视频/文档），只读，永不删
├── wiki/                # 合成文章（AI 读 raw 后写成的可读知识），链接用相对路径
├── modules/             # 可复用能力区：能直接跑的脚本（检索/同步/生成…）
├── outputs/             # 产物区：报告/清单/导出文件（会越堆越多，常覆盖）
├── references/          # 模板
└── .workbuddy/          # 项目级 AI 配置与技能（可选）
```

**为什么这么分**（详见 [`docs/架构总览.md`](docs/架构总览.md)）：
- `raw/` 与 `wiki/` 分离 → 原件永远可追溯，合成稿可随意改写不丢源；
- `modules/` 与 `outputs/` 分离 → 能力（要长期维护）不被产物（会覆盖）淹没；
- `AGENTS.md` 是真相源，其它工具的约定文件只做「转发层」指回它。

### 🔴 双链路：文件链路 + 索引链路

很多人只看到 `raw + wiki` 这一条链路。**真正让 AI 查得准的是第二条链路**——
同一批 Markdown 同时被写进一个 SQLite 库，两条链路靠文件路径对齐：

```
【链路 A · 内容链路】文件即真相源，永远可读、可 diff、可迁移
  raw/（不可变原件）──提炼──▶ wiki/（合成知识）──产出──▶ outputs/（交付物）
        │                        │
        └──── 只入元数据 ────────┘
                    ▼
【链路 B · 索引链路】派生层，可删可重建，永不手改
  md 文件 ──build──▶  kb.db (SQLite)
                       ├─ docs          整篇元数据（path/标题/hash/mtime）
                       ├─ docs_fts      FTS5 整篇倒排（bm25）
                       ├─ doc_terms     TF-IDF 词项倒排（余弦）
                       ├─ chunks       按标题层级切块（带标题路径）
                       ├─ chunks_fts    FTS5 分块倒排
                       └─ raw_metadata 原件元数据（不存正文）
                    ▼
  search ──▶ 整篇 ⊕ 分块 RRF 融合 ──▶ 统一落回 doc.path
```

**三条铁律**：

1. **SQLite 是派生层，不是真相源** —— 删掉 `kb.db` 不丢任何知识，重跑 `build` 即可；
2. **索引与分词器绑定** —— 换分词器必须全量重建，否则查询分词与索引分词不一致，检索质量直接崩；
3. **命中必须能落回文件路径** —— 检索结果一律带 `doc.path`，AI 引用要能点到原文，否则就是幻觉温床。

完整设计、表结构、最小可运行实现（约 80 行 SQLite FTS5）见
[`docs/双链路体系.md`](docs/双链路体系.md)。

## 三、从零搭建（7 步）

> 完整版见 [`docs/从零到一搭建步骤.md`](docs/从零到一搭建步骤.md)。下面是速览。

1. **建目录骨架**：按第二节建好 5 个区 + `AGENTS.md`。
2. **写 AGENTS.md**：填入你的身份、沟通偏好、红线、知识库在哪、怎么查（用 [`templates/AGENTS.example.md`](templates/AGENTS.example.md) 改）。
3. **定沉淀规则**：资料进来先过「三问」（会再用？库里没有？能追溯？），有价值才收。
4. **装检索层**：把 `wiki/` 建索引，让 AI 用检索代替凭记忆写路径（见 [`docs/双链路体系.md`](docs/双链路体系.md)）。
5. **建能力模块**：第一个可复用脚本放 `modules/`，配 README 写清用法 / 调用链路 / 坑。
6. **开技能工作台**：把常用提示词封成卡片（见 [`docs/技能工作台.md`](docs/技能工作台.md)）。
7. **装知识库体系门户**：把 [`kb-hub/`](kb-hub/) 放进知识库，双击 `start-kbhub.bat`，所有系统 / 技能 / 项目一屏直达。

## 四、知识库体系门户（kb-hub）

把零散系统聚合成一个本地仪表盘，并带**每日热度启动台**。

- **启动**：把 `kb-hub/` 放进你的知识库根目录，双击 `start-kbhub.bat` → 自动开 `http://127.0.0.1:8799/`。
- **十个页签**（界面支持**中英一键切换**，选择记在 localStorage）：
  | 页签 | 作用 |
  |---|---|
  | 总览 | 数字看板 + 双链路架构 + 常用工具 + 统一入口 + 最近会话 + 文件类型分布 |
  | 🚪 入口 | 把散落在 `modules/`、`.workbuddy/`、`outputs/` 的去处收敛成一屏，逐个标记「可直达 / 路径缺失」 |
  | 系统模块 | 每个能力模块：打开文件夹 / 读 README / 浏览 / 记一次 |
  | 技能卡片 | 每张卡带源文件路径，可「打开卡片」直接看 SKILL.md |
  | 项目 | 项目笔记与代码目录 |
  | 资源 | wiki 分区 + outputs/raw 一级目录（每个都能点进去） |
  | 🧰 工具 | **三个高频动作就地做**：贴链接下载视频、搜本机聊天记录、生成二维码 |
  | 文件 | **内置文件浏览器**：面包屑导航、上级 / 刷新、点目录进入、点文件用系统程序打开 |
  | 🔍 全库检索 | **三链路 RAG**：FTS5 关键词 + BGE 语义向量 + 字级 substring 融合；「问知识库」组装带引用的上下文包（配置见 `kb-hub/README.md`） |
  | 🔥 每日常用 | 按「频率 × 30 天衰减」排序，每天看这一屏按需点用 |
- **点用即记录**：每次「打开」或「记一次」写入 `usage.json`，按 *使用频率 × 30 天时间衰减* 算热度。
- **零依赖**：仅用 Python 标准库，不污染环境，方便迁移，也能打包成单文件 exe（见 `RELEASE.md`）。
- **路径健壮性**：前端用 `data-*` 属性传参（不是拼 `onclick` 字符串），后端再做斜杠统一 / 相对路径补全 / 插件版本漂移自愈，避免 Windows 反斜杠被 JS 当转义吃掉导致「找不到路径」。
- **端口占用自动顺延**：8799 被占时自动试 8800–8808，不会静默启动失败。
- **示例模式可见**：没生成真实清单时，页面顶部明确提示「当前是示例清单」，不会让人以为坏了。

> 门户只绑 `127.0.0.1`（本机），打开动作在本机执行——**不暴露到局域网**，符合隐私原则。

## 五、技能卡片与提示词管理

「技能工作台」把技能 / 模块 / 提示词统一成卡片：搜索、收藏、置顶、一键复制话术、话术编辑、导出备份。
**提示词资产类卡片** = 把你立下的规矩（复用副本不改原版 / 上传先问 / 版本三件套 / 去水印 / 决策解释义务…）和 AI 的工作模式固化成可复用话术——这就是「对话提示词封存成卡片」的标准动作。

详见 [`docs/技能工作台.md`](docs/技能工作台.md) 与 [`templates/wiki/提示词资产/`](templates/wiki/提示词资产/)。
