# HANDOFF · 交接与已踩过的坑（开源仓库侧）

> 只追加，不删改历史条目。规则：**已踩过的坑写在这里**，别让下一个人再踩一遍。
> 本文件只收录可公开发布的通用教训；本机路径、真实项目名、真实业务词表一律不写。

## 2026-11-06 · W2 双代码库收敛收尾

1. **「文件存在」不等于「能力生效」**：`read_xls` 两侧都写了函数，但两侧 `requirements-extra.txt` 都没声明 `xlrd`、venv 也没装，`except Exception: return ""` 把 ImportError 静默吞掉，能力从未真正跑过。补依赖后必须造一个真实 600 行 `.xls` 跑出字符数，不能只看 `import` 成功。
2. **双库同步不能整文件覆盖**：两侧各有对方没有的修复。先按功能点定性（通用能力 / 隐私词表 / 本机环境 / 库结构配置），再逐项合并；配置值差异显式登记保留。`diff_repo_prod.py` 每周随自检跑一次防再分叉。
3. **一次性合并脚本必须幂等**：插入文本里若仍含锚点会重复插入（`.github` 条目变 2 条）；AST 替换函数时尾部空行会累积，导致每次重跑都判定「有改动」。写完连跑三次验证 `[skip] 已就位 / 改动:(无)`。
4. **覆盖率口径只认 `vec_tables.diff_report`**：手写 SQL 四表校验会与 `doctor` 口径分叉，出现「体检说 100%、回填说有缺口」的互相打脸。统一到单一实体。
5. **并行窗口会改同一个文件**：合并前先备份并跑一遍基线；出现 FAIL 时先做「合并前备份 vs 当前版」对照，确认归因，不要急着改别人的代码或改测试断言掩盖决策。
6. **发布门禁用 `privacy_scan.py --git-only`**：默认全量扫描会连 `.gitignore` 掉的 Release 资产一起扫，几十条噪声压过真实信号。脱敏后再推送。
7. **只写可取证的终态**：`async=true` / `status=0` / `exit 0 + 文件存在` 一律记 ⏳，不写「完成」。另外 `run_tests.py --ci | tail` 打印的 `rc=0` 是 `tail` 的退出码，不是套件的；按输出内容判定。
8. **评测集封顶就测不出增益**：KG 一跳扩展在 30 条多跳集上 `R@5=1.0000`，无论加不加都满分，`Δp95=+48ms` 只会被门禁判 FAIL。结论要写成「靶子太近」，另找更难的集复测，而不是「能力不行」或「门禁太严」。
