## [1.1.0] - 2026-11-10（W12 · LLM 能力层完善与工程化）

> **决策理由**：库主 2026-11-09 拍板「LLM 常驻开启」后，能力层虽已「五件套齐、默认 off、小样本验过」，
> 但缺三样东西：① 「常开＝0 在线延时」的**前提没有机器判据**（后续窗口可能把 3.3s 调用接进同步链路）；
> ② 全量结论、成本、断点续跑、发版没有工程化件，只到「能跑」不到「可常驻 / 可复现 / 可发版」；
> ③ W12 卡 A–F 六段仍是未开始状态。本轮按卡片动作清单全量落地，**不推翻 W5 主链路判定**，
> 全部能力仍只在离线 / 批处理侧，隐私红线与 C4「模型不自证」不变。版本号按新增能力升 minor。

### 一、新增能力（7 个可运行脚本）

| A | `llm/llm_path_guard.py` | 在线入口零 `import llm_kit`（rc=0）；故意插 import 判 BLOCK（5/5 自测） |
| B | `llm/b3_audit.py` | 41/41 有结论、降级率 ≤5%、只加属性不改拓扑、关开关复跑逐条一致（4/4） |

### 二、能力层自身升级（改前原版备份在 `state/*.bak-20261110-W12`）

- `llm_kit.py`：`cache_key` 支持可选 `prompt_version`（**不传时拼串逐位不变**，不动别的窗口缓存）；
  `cache_get` 支持 TTL（默认 0＝永不过期，可复现优先）；trace 记版本。
- `enhance.py` / `b3_review.py`：模板内容 sha1 即版本号——改提示词自动失效旧缓存，无需手工 drop。
- `cli.py --selftest` 加版本键断言（9/9 通过，含 3 类硬拦 / 2 类软替换 / 默认 off 降级）。
- `release_verify.py`：C7 扩判「在线入口零引用」，接进交付闸门；复跑 `PASS_WITH_WAIVERS` / 0 BLOCKED。
- `llm/README.md`：写明离线边界、六段命令、实测快照、已知限制、判据→产物对照。

### 三、口径订正与边界（诚实标注）

- **「8 连发即 429」不是常量**：11-10 真跑 6 连发成功 4 / 30s 超时 2 / **429 为 0**；
  历史 trace 仍有 10 条 429。不因单次没触发就上调并发，生产保持限速 2.5s + 并发 1。
- **改写 A/B 不预告结论**：p 值、R@5、延迟增量以 `state/rewrite_ab_*.json` 机器取证为准，
  本文件不手写数字；p≥0.05 如实记平，**不用「收益不明显」砍能力**（§5.11 判据 3）。
- **B3 只加属性不改拓扑**：41 条中真知识 7 / 碎片 32 / 429 降级 2（4.88%）；去留归人审，AI 不代删。
- **隐私**：发布前 `privacy_scan.py --git-only` 判干净（167 文件 / 0 BLOCK / 1 条 csv 扩展名 WARN）；
  `state/`、缓存、日志、备份均不进镜像。
- **C4 仍 LIMITED**：人标 0 条，评测数字不可当公开榜单，LLM 不得自当金标。

## [1.0.1] - 2026-11-09（闸门口径订正 · 修一个真 bug）

> 决策理由：首次发布后库主拍板了 D1/D3/D4 三件事（沙盒已删、发版成为常态、LLM 开关常驻），
> 闸门仍按「待拍板」渲染，会和既成事实冲突。**结论本身没变**（仍 `PASS_WITH_WAIVERS`），
> 变的是「闸门说的话」和「闸门不再因一处状态变化而漏打印整段」。

### 修复

- **真 bug：沙盒一删，评测段整段不打印。** 原实现把「D1 沙盒清单」和「评测表」写在同一串
  `lines +=` 里，且整串挂在 `if sb.get("deleted")` 分支下；`sandbox.deleted=true` 后
  评测表被吞掉，验收清单里看不见 any@5 / Wilson 区间 / McNemar 结果。已拆成两段独立追加。
- **D1 段落自相矛盾**：删除后 manifest 写 `sandbox: None`，但 D1 段落仍输出「拍板前先看」。
  改为输出既成事实（已删除、依据、实测冗余、备份位置、空间口径提醒）。
- **总体判定文案过期**：原写「剩 N 项红线需库主书面许可 + N 项运行开关待定」；改为
  「D1 沙盒删除 / D3 发版 / D4 常驻开关均已执行，剩 N 项仍待库主拍板」，N 由决策项的档位标记算。
- **决策项标题**：`待拍板（AI 不动手）` → `决策项（已执行的回填事实 / 未执行的仍归库主）`。

### 不变

- 七项技术闸门结论不变：6 PASS + C4 `LIMITED`（`human_judged=0`），0 BLOCKED。
- 评测数字与口径不变，仍只在本独立脱敏语料内成立，不接主检索链路。

## [1.0.0] - 2026-11-09（首次发布 · 独立脱敏知识图谱子系统）

> 决策理由：这是一个**独立、脱敏、可展示**的图谱子系统，不接主检索链路、不碰生产索引库。
> 首次发布只交付「能力已建成且可复算」的部分；评测数字明确标注为 LIMITED（人工标注 0 条），不当公开榜单用。

### 一、交付内容

- **构建链**：`build_corpus.py`（两级脱敏 → 独立 sqlite）→ `kg_build.py`（`--stats` / `--ablate` / `--add`）→ `kg_search.py`（`1hop` / `ppr` / `hybrid`，含 `--explain` / `--json`）。
- **评测**：`eval_multihop.py`（`--freeze` 冻结题库、`--run` 跑对照），配 Wilson 95% 区间 + McNemar 精确配对检验，不给单点数字。
- **出图**：`viz_export.py` + `build_kg_viz.py` → 单文件 HTML（无外链 script、无 fetch），双击即用。
- **交付闸门**：`release_verify.py`（纯标准库）真读证据生成 `release_manifest.json`（机读）与 `RELEASE.md`（人读），结论不手写。

### 二、LLM 能力层（默认 off）

`llm/` 五件套：OpenAI 兼容客户端 / 出口脱敏门禁 / 结果缓存落盘 / 调用留痕 / 失败降级。

- 默认 `KG_LLM_ENABLED=0`；关掉开关后系统完全可跑，同一批输入命中缓存、结论逐条一致。
- 凭据只读库外环境变量（`AGNES_API_KEY` / `OPENAI_API_KEY`），仓库内任何文件、git、日志、缓存均无密钥。
- 实测（仅描述性，样本小）：关系类型判定 n=10 人工金标，规则 0.30 → LLM 0.70；B3 有类型边抽样 12/41，11 条被判为碎片边。
- **不建**：评测校准、题面生成、命中判定——理由是**模型不能自证**（循环论证），不是省钱。

### 三、验收边界（诚实标注）

- 交付闸门终态 `PASS_WITH_WAIVERS`：技术闸门 7 项中 6 PASS + 1 LIMITED（`human_judged=0`），0 BLOCKED；`release_manifest.json` 为机读原件。
- 语料为 demo-scale（33 篇 / 565 块），定位是方法验证，不切块充数；规模不足属脱敏红线的代价。
- 评测只在**独立脱敏子系统内**成立，不推翻主检索链路的既有判定，也不建议据此接入。
- 沙盒索引快照（4.38GB，过期）已按删除守卫流程备份到库外后删除，属冗余清理，不影响可视化产物。
