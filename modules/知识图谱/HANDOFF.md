# HANDOFF · 交接与已踩过的坑（知识图谱子系统）

> 只追加，不删改历史条目。规则：**已踩过的坑写在这里**，别让下一个人再踩一遍。
> 本文件只收录可公开发布的通用教训；本机路径、真实项目名、真实业务词表一律不写。

## 2026-11-09 · 首次发布（v1.0.0）

1. **交付闸门的条件分支会吞段落**：把「评测表」写进 `if/else` 的 `else` 分支里，沙盒一删、`sandbox.deleted=true`，整个评测段就不打印了——而且不报错。**教训：生成式文档必须用「开关前/后各跑一次 + diff 输出」验证，不能只看 rc=0。**
2. **全量隐私扫描和「待提交内容」扫描是两个判据**：`state/` 下有本机路径与真实姓名的中间产物，全量扫描 block=27，但 `state/` 已被 gitignore，`--git-only` 判据是 block=0。**发布门禁要用 `--git-only`，否则噪声压过真实信号；但也必须真跑一次全量，确认 BLOCK 全部落在被忽略目录里。**
3. **复制副本不能只删关键词**：脱敏语料最初用粗规则，语料只剩 9 篇；改成「硬剔专名/业务类别 + 软替换路径/邮箱占位符」两级后才可用。**过度脱敏 = 把语料杀光，和泄漏一样都是失败。**
4. **文件级 sha1 比对发现不了并行改动**：交付闸门最初用「原版脚本 sha1 是否等于历史常量」判定写隔离，结果并行窗口改了生产脚本就误判 BLOCKED。改成「本轮写操作探针的前后 `(size, mtime_ns)` 差异清单里有没有生产脚本」才是正确边界。
5. **评测集饱和会让能力看不出价值**：小语料上 baseline any@5 一度 0.9167，加不加都一样；换成更难的多跳题面后 baseline 0.63、增强 0.78（p=0.0357、配对 Δ 的 95%CI 下界 > 0）。**靶子太近时，结论要写「测不出」，不要写「能力不行」。**
6. **LLM 环节的真实瓶颈通常不是模型**：首版关系判定只有 0.60 且偶发 429——补主动限速 + 尊重 `Retry-After`、`max_tokens` 提到能闭合 JSON、加两段式 JSON 提取后升到 0.70 且 0 降级。**429 与解析失败属于「设计没做完」，不是「模型不行」，更不该拿来当砍能力的理由。**
7. **解析失败的结果不能进永久缓存**：坏 JSON 一旦落盘就会被反复复现，看起来像「模型一直错」。改为解析失败主动丢弃该缓存项，重放时才可信。
8. **人标为 0 时，任何数字都只能标 LIMITED**：不给自己发「通过」，也不拿模型的判断当金标。人工标注是责任人，AI 只出候选。

## 2026-11-09 · v1.0.1 闸门口径订正

9. **事实变了要改「生成器」，别去手改生成物**：`RELEASE.md` 是机器生成的（文件头就写着「勿手改」），但库主拍板执行完 D1/D3/D4 之后，闸门仍按「待拍板」渲染，于是生成物与事实矛盾。**教训：凡是「执行动作 + 机器生成结论」并存的系统，动作落地的那一轮就必须回写生成器的判据**，否则下一轮重生成会把矛盾再产一遍；改生成物本身只会被下一次运行覆盖。
10. **「已执行 / 已授权」要能机器识别**：把状态写进决策项的档位标记（`L3 减法 · 已执行`、`L2 云端/公开 · 已授权常态执行`），总数就能由代码算出来，而不是人手写「剩 3 项」——人手写的数字迟早会和事实脱节，而且没人会去核。

## 2026-11-10 · W12 能力层工程化（v1.1.0）

11. **文件列表工具默认有条数上限，会骗你说「不存在」**：`state/` 有 100+ 文件时，用 `*` 只回前 100 条，本轮一度以为 41/41 全量取证文件不存在、差点按「首次跑」重摇结果。换精确 pattern 才找到。**搜索半径不足就断言不存在**是反模式；说「库里没有」前先换检索方式复核。
12. **前台长任务被 SIGTERM 掐断时不报错、也没产物**：改写 A/B 评估第一次前台跑，输出只有模型权重加载进度就断了（exit 1 / SIGTERM）。教训：先读输出 + 查产物确认**真的没生成**，再改后台重跑；「命令没抛异常」不等于跑完，`rc` 与终态产物要一起看。
13. **速率上限的经验值会过期**：11-09 记「8 连发即 429」，11-10 真跑 6 连发 429=0、先出现的是 30s `TimeoutError`。别把快照当常量，也**别因为单次没触发 429 就上调并发**（共享端点会波动，历史 trace 里仍有 10 条 429）。
14. **给缓存键加版本必须向后兼容**：直接把 `prompt_version` 拼进所有键，会让别的窗口已落盘的缓存一夜之间全失效（等于「改原版」事故）。正解是「不传版本时拼串逐位不变」，只有显式传版本的调用才换键。
15. **「全库零引用」是错误的闸门判据**：离线批处理 / 评测工具复用 `llm_kit` 恰是能力复用的证据。守卫只扫在线入口（`kb_rag` / `kb_index` / 检索服务），否则 C7 永久假红，闸门就废了。
16. **交接自检里存在既有假红，别为了变绿乱改**：`verify_handoff.py` 的 `section-refs` 把**准则**的 `§32` / `§37.10` 当成 `AGENTS.md` 内部章节，报 70 PASS / 1 FAIL。它在本轮之前就存在；本轮不擅自改校验器（别的模块、可能挂定时任务），如实登记边界。规则要先判前提再套。
17. **远端与本地分叉时别直接 push**：本轮本地 `master` 领先一个别的窗口标注「本地，未 push」的提交，直连 `git push` 会把它一起带上去。改走基于**远端 HEAD** 的独立发布路径，只提交本模块，不动别人工作区。**发版途中远端还会继续前进**（本轮 `4636fea` → `7bac034`）：这时把工作树重置到新 HEAD、重跑镜像脚本再提交即可——镜像内容全由脚本再生，不依赖工作树里的未提交状态；千万别在发布工作树里攒手工改动，否则重置就丢。
18. **评测期间索引被并行重建，会以「段错误」的形式出现，而不是报错退出**：2026-11-11 01:18 跑改写 A/B，另一个窗口正把索引从 4.4 万块重建到 13.9 万块，`load_bge()` 走「向量已更新 → 重载常驻矩阵」路径，进程直接 **rc=139（Segmentation fault）**。**教训：评测必须自带快照守卫**——跑前跑后比对 `bge_model.built_at` / `chunks` / `docs`，不一致就写 `*_INVALID_*.json` 并在结论里写「数字不可用」。不能只看「跑完了」。
19. **精排（rerank）的成本随索引规模爆炸，大到不可跑还会崩**：索引 13.9 万块时单条检索 **13–31s**（4.4 万块时是秒级），且连跑 4 条后 **rc=127** 再崩。**处置不是调参硬撑**：A/B 改「关精排、两臂同配置」（配对设计不受影响），把口径写进报告 `retrieval_config`，让读者知道数字是在什么配置下跑的；要开精排必须单独立项并给延迟预算。
20. **「记平」也是终态，别为了好看去换配置凑显著**：本轮改写 A/B 结果 R@5 0.580 → 0.580、McNemar **p=1.0**，就如实写「未达显著、不做增益断言」，能力保留默认 off。**换题集/换配置直到跑出 p<0.05 属于自欺**；结论为负同样要落盘、要写进 CHANGELOG 与 README，别只留个 JSON 在 `state/` 里没人知道。
