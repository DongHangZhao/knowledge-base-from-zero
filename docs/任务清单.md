# 任务清单：并列任务依次执行并检查

**简体中文** ｜ [English](task-list.en.md)

> 对应「搭开发团队协作规范和交付流程」里的执行纪律。
> 大任务不要一把梭——拆成可独立验证的小项，**执行一项、勾一项、卡住就升级**。

---

## 一、为什么需要清单

- 多步骤任务靠记忆容易漏步、跳步；
- 协作时清单是「已完成 / 阻塞 / 待审」的共识面；
- AI 多 Agent 协作时，清单是共享进度源，避免重复或冲突。

## 二、清单怎么写

每条任务满足：**动作明确 + 有验收标准 + 能标状态**。推荐结构：

```
- [ ] 任务名 ｜ 验收：xxx
```

状态：`pending（待办）/ in_progress（进行中）/ done（完成）/ blocked（阻塞，注明卡点）`。

## 三、执行纪律（依次执行并检查）

1. **先列后做**：动手前先有完整清单；
2. **一次一事项**：标 `in_progress`，做完标 `done` 再开下一条；
3. **每步自查**：对照验收标准，不过不进下一步；
4. **卡住就升级**：blocked 不硬扛，列出卡点交人工/换方案；
5. **收尾反查**：全部 done 后，回看有没有漏的红线/沉淀。

下面就是本仓库搭建时实际使用的任务清单（已执行完毕），作为格式范例：

| # | 任务 | 状态 | 验收 |
|---|---|---|---|
| 1 | 扫描并生成知识库真实清单 + 梳理报告 | ✅ | inventory.json + 报告产出，系统/技能卡/项目/入口四类全部落表 |
| 2 | 构建知识库体系门户（前后端 + 每日热度启动台） | ✅ | API 实测通过，热度计算正确 |
| 3 | 整理 GitHub 开源仓库（去隐私化 · 从零到一） | ✅ | 含 README/示例/文档/门户代码，无隐私数据 |
| 4 | 本地打包 zip + PyInstaller 造 exe + Release 说明 | ⏳ | zip + exe + RELEASE.md 就位 |
| 5 | 收尾沉淀 + 给出使用与发布指引 | ⏳ | 工作日志 + 发布步骤（gh 未登录需先 auth） |

> 注：状态用工具的任务列表实时跟踪，这里是落档快照。

## 五、可复用的空模板

```
## 任务清单
- [ ] 1. 调研 ｜ 验收：输出 ≥3 个方案 + 推荐理由
- [ ] 2. 设计 ｜ 验收：五何齐全，实体最少
- [ ] 3. 实现 ｜ 验收：幂等、可续传、单失败不中断
- [ ] 4. 自测 ｜ 验收：失败用例修复 + 返回码已查
- [ ] 5. 沉淀 ｜ 验收：raw+wiki+索引+日志
- [ ] 6. 发布 ｜ 验收：版本三件套 + 去隐私化 + 说明 md
```
