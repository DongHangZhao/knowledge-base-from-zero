## 0. 为什么不能用单跳集测 1-hop

单跳题（`state/kb_eval_30.json`）的 gt 只有一篇文档，答案就在那一篇里。给这类题加 1-hop 邻居召回，
**邻居全是噪声**：既提不了 Recall（gt 本来就排得到），又必然拉高延迟，实验会得出「1-hop 没用」的错误结论。
1-hop 的价值只在多跳：**答案分散在两三篇文档里，单路召回只能捞到其中一篇**。

所以本集的每一条都必须满足一条硬性结构：**单看第一篇答不出，必须跳到后面某篇**。

## 1. hops 字段的语义（本集定义，与示例文件一致）

`hops = len(gt)` = **回答这条 query 需要读几篇文档**。

- `hops: 2` → 22 条（要求 ≥15 ✅）
- `hops: 3` → 8 条（要求 ≥8 ✅）

## 4. 硬性校验结果（脚本原文）

```
$ /e/_venvs/gpu/Scripts/python.exe -X utf8 _verify_multihop_30.py --matrix

[PASS] 条数 = 30
[PASS] id 唯一且连续 mh01..mh30
[PASS] 50/50 路径全部存在于 kb.db docs.path（共 50 条唯一路径）
[PASS] hops = len(gt)，逐条一致（hops 语义：需要读几篇文档）
[PASS] 无重复 gt 路径
[PASS] hops 分布：hops2=22（要求>=15） hops3=8（要求>=8） 其他=0
[PASS] 30/30 query 均不含任何 gt 文件名原词
...（每条 answer_kw 命中矩阵，见脚本 --matrix 输出）
[PASS] 30/30 多跳性质成立（答案关键词在第一篇不出现、在最后一篇出现）

==== 结果：PASS 30/30 ====
```

校验脚本做了 7 件事：

1. 条数 = 30
2. gt 每条路径都 `select 1 from docs where path=?` 命中（**50 条唯一路径，50/50 存在**）
3. `hops == len(gt)`，且 hops2 ≥15、hops3 ≥8
4. 单条内无重复路径
5. id 唯一且连续
6. query 不含任何 gt 的文件名原词（按 `-`/`_` 拆分文件名后逐词检查）
7. **多跳性质**：每条的 `answer_kw` 必须在**最后一篇** gt 出现、在**第一篇** gt **不**出现 —— 这是「单看第一篇答不出」的机器化证明，不靠人工口说

## 5. 区分力体检（对齐六桶 G1 硬门禁）

结构上「是多跳」不等于「有区分力」。如果一条题纯关键词就能命中所有 gt，那它根本不需要 1-hop，
给它加邻居只会加噪声。所以按 `知识库检索评测体系-六桶去饱和与配对检验.md` §3 的 G1 硬门禁，
对 30 条各跑一次 `mode=kw`、top20，看 gt 落在几名。

## 6. 已知缺口与阻塞（这两条会影响 #41 能不能真跑出数）

### 🔴 阻塞 1：`eval_rag.py` 不支持 `gt` 为数组

现有 `eval_rag.py` 把 `gt` 当**单个字符串**处理：

- 第 107 行 `q, gt = item["query"], item["gt"]` → `gt` 是 list
- 第 190 行 `conn.execute("SELECT id FROM docs WHERE path=?", (it["gt"],))` → **`sqlite3.ProgrammingError: Error binding parameter 1: type 'list' is not supported`**（库里 set/校验这一步直接崩）
- 第 119 行 `if h["path"] == gt:` → list 与 str 比较恒为 `False` → **即使绕过崩溃，30 条也会全部算「未命中」，Recall = 0%**

也就是说：本集按设计格式（多 gt）交付后，**现有 harness 直接跑会崩；就算改成不崩，读数也是全 0**。
需要 Engineer 做两处小改：① `gt` 统一归一化成 list（`gt if isinstance(gt,list) else [gt]`）；
② 命中判定改成「任一 gt 命中即算命中」（Recall/MRR 按 `min(rank of any hit)` 取）。

### 🔴 阻塞 2：`--set multihop` 不存在

`docs/decisions/KG-41.md` 第三节写的复现命令是 `python eval_rag.py --set multihop`，
但 `eval_rag.py` 的 `--set` 只有 `["30","100","both","auto","all"]`，加载器只读
`kb_eval_30.json` / `kb_eval_100.json` / `kb_eval_auto.json`。**按文档跑第一步就 argparse 报错。**
需要加一个 `multihop` 选项指向 `state/kb_eval_multihop_30.json`。

### 补充：`kg_gate.py` / `kg_extract.py` 当前不在模块目录下

`ls kg_gate.py kg_extract.py` 均不存在（KG-41.md 的复现命令第 2、4 步依赖它们）。若在别的分支，
请确认最终落盘路径与文档一致。

### 没有凑数的地方

30 条全部做满，无硬凑。有一点必须说清：**mh05 / mh06 的第三跳指向的是 OCR 产物的具体图片文档**
（`扫描全能王 2026-03-31 20.25.jpg.md` 这类）。这类文档内容是图片的转写，信息量弱于普通 wiki 页。
用它们是为了让「三跳」有真实的第三跳可落（否则第三篇只能拿另一篇 wiki 凑，反而是伪多跳）。
如果 #41 只想测「wiki 页 ↔ wiki 页」的两跳/三跳，可以把这两条剔掉，剩 28 条
（hops2=22、hops3=6）—— 此时 **hops3 不达 8 条的配额**，需要另补 2 条三跳题，
不能直接拿 28 条开跑并声称分布达标。这一点请在剔题前先决定。
