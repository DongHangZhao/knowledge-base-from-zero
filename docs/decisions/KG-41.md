# #41 知识图谱 1pt 实验 · 决策记录

> 判定时间：2026-11-04 ｜ 判据**开工前写死**：R@5 ≥ +3.0pp **且** p95 ≤ +150ms
> 环境：生产库副本 `state/_kg_sandbox.db`（4.7GB，字节与主库一致）+ `E:/_venvs/gpu`（torch 2.14.1+cu126, CUDA）
> 评测集：`kb_eval_multihop_30.json`（30 条真多跳，含锚点实体，过 30/30 门禁）

## 一、结论

**归档不做（不实现插件层）。**（pass = `False`）

| 口径 | baseline | +1hop | Δ |
|---|---|---|---|
| `any@5`（任一 gt 命中，eval_rag 现有口径） | 30/30 = 100.0% | 30/30 = 100.0% | ±0 |
| **`all@5`（所有 gt 都进 top5 = 真多跳答对）** | **15/30 = 50.0%** | **14/30 = 46.7%** | **−1 条（−3.3pp）** |
| 第一跳中、第二跳空（1-hop 的机会窗口） | 10 条 | 10 条 | ±0 |
| p95 延迟 | 494ms | 630ms | **+136ms** |

按判据：R@5 **+0.0pp**（新口径 −3.3pp）远低于 +3pp → **FAIL**。延迟虽在 +150ms 内，但收益不达标，不看延迟也要 FAIL。

**1-hop 一条都没救回，还弄坏了一条**（mh29 `all: True → False`）。

## 二、🔴 但「图谱无效」这个结论**不成立** —— 失效点在实体抽取

这是本记录最重要的一段。不看这段，未来的自己会误以为「图谱方案本身没用」，从而错过一个真正值得做的事。

诊断 `mh01` 的实际抽取结果：

```
query: 某医院集群项目里排在最后才实施的那套，后端用的什么语言和框架
抽出实体: ['该集群', '五大', '后端', '实施', '排在', '最后']
1-hop 返回 10 条，含 gt 末篇? False
top3: ['求职简历与自我介绍.md', '小六壬入门教学（重发）.md', '2023-11-04-打开心智.pdf']
```

**「某医院集群项目」被切成了「该集群」「五大」「系统」三个碎词**；「系统」因 df 太高被过滤掉，剩下「该集群」「五大」这种**低区分度泛词**。拿「该集群」做 1-hop，自然召回一切提到"该集群"的文档 —— 包括求职简历。

`mh05` 侥幸命中（`含 gt 末篇? True`），是因为「培训」恰好命中了 OCR 培训签到文档。

**失败链条**：
1. 全库建侧表两次超时（28min / 27min 未完成）→ 只能缩小到 196 篇 gt 文档
2. 为压速度改用 `jieba.cut`（去掉词性标注）→ 没有名词短语边界
3. 纯切词 + df 过滤 → 长实体（"某医院集群项目"）被拆散，短泛词（"该集群"）被保留
4. 泛词做 1-hop → 引入无关文档 → 收益为负

⇒ **结论应是：这套实体抽取器不具备做图谱的前提。** 若要走图谱路线，前置条件是能抽出**完整短语实体**（NER、n-gram 短语挖掘、或借 `docs.title` + 别名表维护种子实体），而不是拿分词碎片硬凑。

## 三、两个方法学教训（比结论更值钱）

### 1. `any@5` 测不出多跳，差点得出「100% 完美」的假结论

eval_rag 现有口径是「**任一** gt 命中即算 hit」。多跳集 gt = [第一跳, 第二跳]，第一跳（总览页）极易被关键词路命中 → **baseline 直接 100%**，treat 没有提升空间。

第一次跑出来就是 `baseline R@5=100.0% / treat R@5=100.0%`。如果就此收工，会得出「图谱无害也无用」，而真相是**这把尺子量不出东西**。

改用 `all@5`（所有 gt 都进 top5）后，baseline 立刻降到 50%，问题才显形。

**一般化：多答案评测必须用 all-hit，不能用 any-hit。** any-hit 在多答案场景下会随答案数增多而虚高。

### 2. 全库建侧表两次超时，暴露「分段测速 × 全量」的估算错误

分段测速（1000 chunk）显示 `jieba.cut` 全库只要 1.7~2.7 分钟，实际跑 27 分钟未完成，差 10 倍以上。

原因不在分词算法，而在**单进程累积 11 万条结果（内存涨到 600MB+）+ 建立 WITHOUT ROWID 侧表**这一段。分段测速只测了分词，没测累积与写库。

**一般化：测速必须测「端到端」；分段测速只用于横向比较算法，不能线性外推到全量。**
