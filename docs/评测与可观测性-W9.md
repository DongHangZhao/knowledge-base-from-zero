> Raw: 无（本页为工程结论，无外部原件；可复跑证据为 `modules/知识库索引/w9_eval/` 下脚本与本地 JSON 产物）

## 一、一句话结论

**自建评测体系的分辨力比通用框架更强**（去饱和主集 + 六桶方法学 + McNemar 配对检验 + 掉 >2pp 拦截）；
RAGAS / DeepEval 这一层只用于**对外口径对齐**，不替换、不并联成第二把尺子去改门禁。

> 面试时可答：「自建六桶 + 配对检验负责判『有没有变好』，
> 并按 RAGAS 官方指标定义做了本地对照，写清哪些等价、哪些不可比。」

## 二、为什么不装 ragas / deepeval 包

装前先核实了官方文档（三件套：标题 + URL + 访问日期）：

| 指标 | 官方默认实现 | 是否需外部 LLM |
|---|---|---|
| Faithfulness | `AsyncOpenAI()` + `llm_factory("gpt-4o-mini")`，拆答案主张逐条判上下文支持 | ✅ 需要 |
| Answer Relevancy | 由答案反推 query 再算相似度 | ✅ 需要 |
| Context Precision | `ContextPrecision(llm=...)` 逐块比对 reference | ✅ 需要 |
| Context Recall | 把 reference 拆成主张，逐条判能否归因到检索上下文 | ✅ 需要 |

- Faithfulness — Ragas — https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/faithfulness/ — 访问 2026-11-10
- Context Precision - Ragas — https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/context_precision/ — 访问 2026-11-10
- Context Recall - Ragas — https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/context_recall/ — 访问 2026-11-10

**决策**：默认调用链带云端外发路径，与「隐私不上云 + 出口门禁写在必经处」冲突。
改走官方**同时提供**的纯本地变体定义 —— `IDBasedContextPrecision` /
`IDBasedContextRecall` / `NonLLMContextPrecisionWithReference` —— 用本库「gt = 文档路径」直接对齐，
零依赖、可复现、一键可开。这不是「砍掉 LLM 能力」：LLM 通道另建（见 §五）。

## 三、指标映射表（逐项判等价 / 部分等价 / 不可比）

| 自建指标 | RAGAS 指标 | 判定 | 为什么 |
|---|---|---|---|
| `R@5`（all@5，多答案集合命中） | `context_recall`（IDBased） | **等价**（口径不同） | 两者都是 `\|gt ∩ top5\| / \|gt\|`；区别在自建按**题**判命中、RAGAS 按**块 ID 集合**算，gt 为文档路径时二者同形。🔴 分母不同：自建排 E 桶负样本，RAGAS 无 reference 时无定义 |
| `MRR@5` | `context_precision`（排名加权） | **部分等价** | 都奖励「相关项排得靠前」，但 MRR 只看第一个命中位次，CP@K 是 `∑(Precision@k × v_k)/相关项数` 的全排名加权；MRR 无法表达「多个相关项分散在后排」 |
| `precision@k`（`metrics.py`） | `IDBasedContextPrecision` | **等价** | 官方公式 `\|retrieved ∩ reference\| / \|retrieved\|`，与本地 `precision_at_k` 同形 |
| `空检率` / `零结果率` | 无对应指标 | **不可比** | RAGAS 四指标全部假设「已检索到上下文」，不建模零结果；这是可观测性门禁（>5% 告警），不是 RAG 质量分 |
| `引用准确率`（`answer_eval.py`） | `faithfulness`（弱代理） | **不可比** | 引用准确率判「答案里引的路径是否真实且在上下文内」，是**引用真实性**；faithfulness 判「事实主张能否被上下文支持」，是**事实一致性**。抓「张冠李戴」要靠后者，弱代理做不到 |
| `context_support`（词面覆盖弱代理） | `faithfulness` | **部分等价 · ⏳ 弱代理** | 都能抓「凭空造词」，都抓不住「把 A 的事安到 B 头上」；官方要 LLM 拆主张，本地只算实词覆盖 |
| `query×答案` 词面重叠 | `answer_relevancy` | **不可比 · ⏳ 弱代理** | 官方要 LLM 从答案反推 query；词面重叠连「答非所问但词全对」都抓不住，只做接口占位，不许当质量分 |
| `eval_gate` 掉 >2pp 拦截 + McNemar | DeepEval `assert_test(threshold)` | **等价（门禁语义）** | 都是「指标掉破阈值 ⇒ rc≠0」。区别：自建多一层配对显著性检验，判「变好」比单点阈值严 |
| 六桶方法学 / 去饱和主集 | 无对应 | **不可比 · 自建强项** | 通用框架不管题集饱和度与桶分布；前 20 条冒烟 95% 的假象正是靠分层设计避开的 |

🔴 **两把尺子的分不可比**：分层均匀抽样（每桶等量）≠ 全集按桶加权，报数必须写清样本量与抽样方式。
🔴 **生成侧两个指标恒标 ⏳**：人工 gold = 0 条、`judge_calibration.py status` → `UNCALIBRATED rc=2`，
未校准前不判好坏、不进上线/回滚决策、不写进简历数字。

## 四、追踪与可观测

- OTel 语义 span 四段 `embed → retrieve → rerank → generate`，OTLP/JSON 兼容结构，纯标准库（未装 SDK）。
- 🔴 **本库是检索系统，无 generate 段** —— 第四段如实标 `kb.no_generate_stage=true`、耗时 0、状态 `UNSET`，
  不伪造答案也不伪造耗时。
- 三张门禁指标：零结果率（>5% 告警）、index freshness（抽 20 篇对源文件中位年龄）、每层耗时 p95。
- 🔴 不接 Langfuse / Arize Phoenix / 任何云端观测平台；span 默认 off，`KB_W9_TRACE=1` 一键可开。
- 本地看板为单文件 HTML（零 CDN、离线可开）。

## 五、LLM 能力：必建、默认 off、一键可开

三级 judge 开关，全部本地可跑：

| 档 | 实现 | 外部依赖 |
|---|---|---|
| `local`（默认） | 词级弱代理 | 无 |
| `claim` | 本地结构化主张拆分 + 逐句覆盖 | 无 |
| `llm` | 复用 `llm_kit.py` 五件套（客户端 / 出口门禁 / 缓存 / 留痕 / 降级） | 库外环境变量；未配自动降级，不中断 |

`--ab` 给 local vs claim 的小样本差值（纯本地闭环，不依赖外部 key）。
🔴 差值只证明「开起来真能跑」，**不是质量结论**；LLM 不得自当评测金标，golden set 人标校准仍归库主。

## 六、公开 CI 口径

见 [`.github/workflows/eval-ci.yml`](../.github/workflows/eval-ci.yml) 与
`modules/知识库索引/w9_eval/w9_ci.py`。三态严格区分：

- **PASS** — 真跑 rc=0 且判据通过（离线回归套件、`eval_gate --self-test`、W9 五件套自测、隐私终审）
- **SKIP** — 设计上不具备条件：仓库侧只有脱敏示例集、没有冻结主集 manifest 与生产基线
  ⇒ **明确打印原因，单列计数，不算 PASS**
- **FAIL** — 真跑 rc≠0 ⇒ 整条 CI rc≠0，**绝不洗成 SKIP**

编排器用 `subprocess` 显式取每条 returncode（GitHub Actions 的 `run: |` 多行默认不逐条拦，
一条挂了后面照跑会「看上去全绿」），文件末尾 `sys.exit(main())` 保证 rc 真的存在。

🔴 **CI 绿 ≠ 可以发布**：词表按隐私红线不得入库，CI 里只有 L1+L3 规则；
发布前必须在本机带 `~/.kb_privacy_terms.txt` 再跑一次 `python tools/privacy_scan.py --git-only`。

## 七、本窗口不做的事

- 不替换 `eval_gate.py`、不动冻结主集 sha1、不改任何默认参数
- 不代填人标 gold、不用 LLM 合成答案凑人标、不写「已评测」
- 不把生产 184 条（含真实业务 query）推上公开仓库
- 零 push / 零上传 / 零发布 —— 完成 ≠ 发布，对外动作归库主单独授权
