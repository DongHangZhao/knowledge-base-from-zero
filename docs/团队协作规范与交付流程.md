# 团队协作规范与交付流程

**简体中文** ｜ [English](team-collaboration.en.md)

> 当知识库从「个人外置大脑」升级为「小团队协作平台」时使用。
> 适用：多人维护同一知识库、或一起做开发交付。核心目标——**降低协作熵、保证可交接、红线不越界**。

---

## 一、协作规范

### 1. 角色与责任（RACI 简版）
| 事项 | 负责人(R) | 审批(A) | 知会(I) | 执行(C) |
|---|---|---|---|---|
| 知识库结构变更 | 架构 owner | 全员评审 | 全员 | 执行人 |
| 红线/准则修改 | 架构 owner | 全员评审 | 全员 | — |
| 模块脚本上线 | 模块 owner | 架构 owner | 相关人 | 开发 |
| 对外发布/上云 | 发布 owner | 知识库 owner | 全员 | 发布人 |

> 关键：**知识库 owner 是最终责任人**，AI 是任一执行实例，不做判断替代。

### 2. 分支与目录归属
- 代码：Git 主干保护，改动走分支 + PR；
- 知识库：先划**目录归属**（后写盖先写），避免两人同时改同一份；
- 子 Agent / 协作者：先只读调查，主 Agent 统一改；子 Agent 的结论必须过人工校验。

### 3. 代码评审（四眼原则）
- 任何合并至少 1 人 review；
- review 看三件事：**是否动到不该动的（红线/原版模块）、是否有出处、是否附测试**；
- AI 生成的代码默认待验，最佳模型现场推理准确率也只有约 35% —— 必须人工校验。

### 4. 红线分级（全员必须背）
| 级 | 内容 | 处理方式 |
|---|---|---|
| **L1 绝对禁止** | 隐私数据上云/进 git/进公众号；改原版模块；时间快照清理；编路径 | 越权即事故，先停再做 |
| **L2 必须先问** | 上传云端前；危险删除；越区写 | 列清单等过目 |
| **L3 建议** | 去水印双份；全中文对照；折腾工具 ≠ 进步 | 可以不听但解释 |

### 5. AI 协作四机制
1. **连续调查**：不只答一次，追到底；
2. **背景不断**：任务书三要素（查什么 / 能做什么 / 交回什么）；
3. **消息异步**：发送 ≠ 已读 ≠ 照做；
4. **轮结束 ≠ 会话结束**：上下文要跟着人走。

### 6. 冲突裁决
**哪个方案增加了更少的实体，哪个赢。** 分不清时，选那个能写进 CHANGELOG「决策理由」、三个月后自己能看懂的。

## 二、交付流程（六节点 + 检查清单）

每个节点结束前**逐项勾选**，任一未过不进下一节点。

### 节点 1 · 需求确认
- [ ] 需求书面化（角色/规则/任务/成功标准）
- [ ] 成功标准可验证
- [ ] 边界与红线已识别
- [ ] 复用检查：先查有没有轮子（不重复造）

### 节点 2 · 方案设计
- [ ] 给出 ≥2 个备选 + 淘汰理由
- [ ] 通过五何（为何做/为何这样/边界/怎么验/何时停）
- [ ] 实体最少原则审查
- [ ] 高风险项已标注审批点

### 节点 3 · 实现
- [ ] 只碰必须碰的（精准修改）
- [ ] 增量幂等、可断点续传
- [ ] 单条失败不中断整体，记进汇总
- [ ] 注释写「为什么」，不写「做什么」

### 节点 4 · 自测
- [ ] 有失败用例验证修复
- [ ] 命令/脚本返回码已查（静默失败必暴露）
- [ ] 检索/汇总结果与预期比对
- [ ] 交付前目检（跑完 ≠ 内容对）

### 节点 5 · 沉淀
- [ ] 资料过三问过滤器，落 `raw/`+`wiki/`
- [ ] 是规矩 → 升准则版本号；是知识 → 写 wiki
- [ ] 更新索引（`kb_index build` 之类）
- [ ] 记日志 + 记忆

### 节点 6 · 发布
- [ ] 版本三件套（VERSION + CHANGELOG 含决策理由 + 备份快照）
- [ ] 对外内容最终校验（人工）
- [ ] 隐私数据已剥离（去隐私化）
- [ ] 发布说明（md）随资产附带

---

## 三、与知识库的结合

每完成一个节点，把**该节点的决策与坑**写进 `wiki/`（项目笔记）或 `modules/<模块>/README.md` 的「踩坑」段。知识库的复利来自：**流程里产生的认知，立刻变成可检索的知识**。

## 四、度量与复盘

- 周级：沉淀闸门自检（说要沉淀 vs 真沉淀了）；
- 月级：复盘红线触碰、复用率、返工率；
- 任何人可发起「减法提案」（按 L1/L2/L3 分级审批），但默认姿态是「只加不减」。
