# 架构总览：为什么这样分四区 + 一份真相源

**简体中文** ｜ [English](architecture.en.md)

> 知识库不是「又一个文件夹」，而是一套让 AI 能复用你知识的操作系统。架构的每一刀都是为了**减少实体、降低耦合、可追溯**。

## 一、四区职责

| 区 | 性质 | 谁写 | 能不能删 | 典型内容 |
|---|---|---|---|---|
| `raw/` | 不可变原件 | 你 / AI 下载 | **永不删**（时间快照） | PDF、图、视频、Word、公众号原文 |
| `wiki/` | 合成文章 | AI（读 raw 后写） | 可改 | 项目笔记、学习笔记、技术文档、提示词资产 |
| `modules/` | 可复用能力区 | 你 / AI | 改要慎（可能挂定时任务） | 检索、同步、生成、爬虫等脚本 |
| `outputs/` | 产物区 | AI / 工具 | 可覆盖 | 报告、清单、导出文件、图片 |

**核心原则**：原件与合成分离、能力与产物分离。混在一起的结果是——产物把原件淹没，合成稿改写丢了源，能力脚本被临时文件污染。

## 二、为什么 `raw/` 只读不删

- 可追溯：任何合成结论都能指回原件；
- 防丢失：AI 合成可能出错，原件是纠错基准；
- 时间快照：运势/推演/日志等同日多次 = 多个独立批次并存，**按日期清理论断错误**。

## 三、为什么 `AGENTS.md` 是真相源

- 规则只写一处，其它工具的约定文件（`CLAUDE.md`/`.cursor/rules` 等）只做**转发层**指回它；
- 改规则只改 `AGENTS.md`，避免真相源分裂；
- 跨工具通用：Codex / Claude Code / Qoder / Cursor 原生读，Trae 桌面版需手动开两个开关，网页版 AI 读冷启动包。

## 四、双链路：内容链路 + 索引链路

四区是**链路 A（内容链路）**：文件即真相源，可读、可 diff、可迁移。
但几百篇之后，AI 凭记忆写路径一定会出错。所以需要**链路 B（索引链路）**：
同一批 Markdown 被 `build` 进一个 SQLite 库，检索时命中「整篇 + 分块」并**统一落回 `doc.path`**。

```
raw/ ──▶ wiki/ ──▶ outputs/                 链路 A：真相源
          │
          └──build(增量)──▶ kb.db (SQLite)   链路 B：派生层，可删可重建
                              └──▶ search ──▶ top-k + doc.path
```

三条铁律：**SQLite 是派生层不是真相源 / 索引与分词器绑定（换分词器必须全量重建）/ 命中必须能落回文件路径**。
完整表结构、融合公式、最小可运行实现与七个坑 → [`双链路体系.md`](双链路体系.md)。

> ⚠️ 最容易犯的错：改了 md 忘记 `build`。**过期索引比没有索引更危险**——它会让 AI 自信地引用旧内容。

## 五、实体最少原则

每次想加一个目录/脚本/约定，先问「砍掉它会怎样」——**砍掉没影响就砍掉**。冲突裁决统一用一句话：**哪个方案增加了更少的实体，哪个赢。**
